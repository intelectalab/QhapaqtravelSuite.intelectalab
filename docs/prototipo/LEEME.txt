QHAPAQ TRAVEL SUITE — Prototipo funcional
SaaS multi-tenant de gestión integral para agencias de viajes y operadores turísticos
Basado en: DOC-PROC-001 v1.0 (Flujo de Procesos) y Especificación Funcional PRD (Productos Turísticos)

INSTALACIÓN
1. Subir el contenido de esta carpeta a public_html (o a una subcarpeta).
2. Abrir index.html en el navegador. No requiere servidor de aplicaciones, base de datos ni compilación.
   (También funciona abriendo index.html directamente desde el disco.)

TECNOLOGÍA
HTML5 + CSS3 + JavaScript vanilla. Sin frameworks ni librerías externas (solo la tipografía Plus Jakarta Sans desde Google Fonts).

USO
- En la pantalla de inicio elija un perfil de demostración. Cada rol tiene su propia experiencia:
  · Back-office interno: Tenant Admin, Manager, Ventas (solo su cartera), Operaciones, Finanzas, Contabilidad.
  · Portales externos: Agencia B2B, Cliente, Pasajero, Extranet de proveedores (solo sus datos).
  · App móvil: Guía / Conductor (solo sus asignaciones).
  · Consola de plataforma: Super Admin SaaS (tenants, planes, jobs; sin datos comerciales).
- Cada pantalla exige un permiso; si se intenta abrir por URL una pantalla no permitida, se muestra 403
  y el intento queda en auditoría. La matriz completa está en Administración › Roles y permisos › Mapa de acceso.
- Desde el menú de usuario: "Cambiar de rol (demo)" y "Restablecer datos de demostración".
- Los cambios se guardan en el navegador (localStorage) solo para la demostración.
- Todos los datos (empresas, personas, proveedores) son ficticios. Fecha de referencia: 29/09/2026.

NOTA
Prototipo navegable para validación funcional. Las integraciones externas (OSE/SUNAT, pasarela de pagos,
WhatsApp, proveedores, OTA/GDS) están simuladas y deben validarse antes de producción (DOC-PROC-001 §23).
